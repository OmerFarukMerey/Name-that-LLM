## The change: the n-gram SVC trusts host passages more than public ones

Upstream loads its SVC pre-fitted (`ntl627-svc-prefit` in lightningv08's
[asset dataset](https://www.kaggle.com/datasets/lightningv08/ntl-olmo2-native24-final-inference-assets)): four TF-IDF
views (raw characters, words with punctuation, word shapes, small words) and a LinearSVC fitted on 2,699 host passages
**plus 75,783 public passages (Nishant Dahal's `pool_v4`), all at weight 1**. It is the first term of the main blend.

The public passages were generated by many people, with other prompts, settings and providers. Pool-trained members
score 0.03–0.04 higher on grouped CV than on the LB, which points at exactly that mismatch. So I refit the same SVC
offline with sample weights, and a public passage now counts as weaker evidence than a host passage:

| passage | sample weight |
|---|---:|
| host passage (train.csv) | 1.0 |
| public, and also in fleongg's [quality-selected pool](https://www.kaggle.com/datasets/fleongg/ntl-quality-selected-public-svc-pool) | **0.3** |
| public, everything else | **0.1** |

```python
in_quality = pool.text.isin(set(quality_pool.text))           # 35,116 of the 75,783 pool rows
w = np.r_[np.ones(len(train)), np.where(in_quality, 0.3, 0.1)]
svc = LinearSVC(C=0.5, random_state=42, max_iter=5000, class_weight="balanced")
svc.fit(X, y, sample_weight=w)  # X: upstream's own vocabulary and idf, train rows first, then pool_v4
```

A sample weight `w` is the same as fitting that row with `C × w`, so the public rows are regularised more strongly. The
quality pool drops passages with label conflicts, paragraph breaks, code or thinking traces, refusals and format problems.
With all weights at 1, the same script reproduces upstream's published readout to 2e-7, so the weights are the only
difference. The refit ships in upstream's file format as
[ntl-svc627-quality-tiers](https://www.kaggle.com/datasets/omerfarukmerey/ntl-svc627-quality-tiers), so upstream's own
`cached_svc` loads it.

Down-weighting makes the SVC's probabilities flatter, and the blend uses its log-probability directly, so the member would
quietly lose influence. The calibrated temperature on out-of-fold predictions rises from 3.23 to 5.31, so the one
blend line becomes `total=1.64*clipped_logp(svc_scores)` (5.31 / 3.23 ≈ 1.64). That keeps the SVC's share of the blend
where the upstream authors tuned it.

## Evidence (CPU only, reproducible)

Prompt-grouped 5-fold CV on the 2,699 host passages, same 4-view SVC, same pool. Pool passages whose content-word TF-IDF
cosine to any train passage is ≥ 0.3 are dropped first, so no validation prompt leaks in through the pool. The interval
is a 95% paired bootstrap over prompts of the gain against the upstream weighting.

| SVC pool weighting | balanced accuracy | gain vs upstream (95%) | calibrated log loss |
|---|---:|---:|---:|
| all public rows 1.0 (upstream) | 0.468 | | 1.569 |
| all public rows 0.3 | 0.483 | +0.005 to +0.025 | 1.506 |
| quality rows 0.3, others 0.1 (**this notebook**) | **0.496** | **+0.016 to +0.040** | **1.475** |

The optimum is broad, which is reassuring for transfer: quality weight 0.3–0.5 and the rest 0.05–0.15 all land at
0.495–0.496. Dropping the low-quality rows entirely (weight 0) is worse (0.484), so they still help, just less.

**Tried and not better for this member:** larger pools (122k: 0.470, 120k: 0.461), per-row importance weights from a
host-vs-pool domain classifier (0.472), other C values at weight 1 (0.462–0.476), class balancing on weighted counts
(no change), refitting on pseudo-labelled test passages (worse in simulation).

## Other differences from upstream (no effect on predictions)

1. **Mount paths.** A notebook saved today mounts every dataset at `/kaggle/input/datasets/<owner>/<slug>`. Upstream
   hard-codes the older short paths for two of them (its asset dataset and `nlm-l24-adapters`), so those strings are
   rewritten (145 + 2 occurrences). Without this, a fresh copy fails its input checks on the hidden rerun.
2. **A commit-time self-test** (the two cells before the run cell). On the 3-row public test the notebook writes a
   canned preview and skips inference, so a broken change would only show up hours into the hidden rerun. The self-test
   checks, on CPU: the SVC path and the ×1.64 line, the sha256 of every refit file, that the refit reproduces its saved
   logits on the 3 public rows, its label order on 300 train passages, all 160 upstream input checks, and 2 GPUs. On any
   failure it deletes the preview submission and raises.
