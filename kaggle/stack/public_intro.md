## The change: the n-gram SVC trusts host passages more than public ones

The stack's strongest single member is a 4-view TF-IDF LinearSVC (raw characters, words with punctuation, word shapes,
small words), at blend weight 1.0. Upstream fits it on 2,699 host passages **plus 75,783 public passages, all at weight 1**.

The public passages were generated by many people, with other prompts, settings and providers. The forum's
pool-trained members score 0.02–0.04 higher on grouped CV than on the LB, which points at exactly that mismatch. So here
a public passage counts as weaker evidence than a host passage:

| public passage | sample weight |
|---|---:|
| host passage (train.csv) | 1.0 |
| public, and also in fleongg's [quality-selected pool](https://www.kaggle.com/datasets/fleongg/ntl-quality-selected-public-svc-pool) | **0.3** |
| public, everything else | **0.1** |

A sample weight `w` is the same as fitting that row with `C × w`, so the public rows are regularised more strongly than
the host rows. The quality pool (already attached to the upstream notebook, but unused there) drops passages with label
conflicts, paragraph breaks, code or thinking traces, refusals and format problems.

Down-weighting makes the SVC's probabilities flatter. In the blend they enter as `W_SVC × log p`, so the member would
quietly lose influence. The calibrated temperature on out-of-fold predictions rises from 3.23 to 5.31, so `W_SVC` is
multiplied by **5.31 / 3.23 ≈ 1.64**. That keeps the SVC's share of the blend where the upstream authors tuned it.

## Evidence (CPU only, reproducible)

Prompt-grouped 5-fold CV on the 2,699 host passages, same SVC, same pool. Pool passages whose content-word TF-IDF cosine
to any train passage is ≥ 0.3 are dropped first, so no validation prompt leaks in through the pool. The interval is a
95% paired bootstrap over prompts of the gain against the upstream weighting.

| SVC pool weighting | balanced accuracy | gain vs upstream (95%) | calibrated log loss |
|---|---:|---:|---:|
| all public rows 1.0 (upstream) | 0.468 | | 1.569 |
| all public rows 0.3 | 0.483 | +0.005 to +0.025 | 1.506 |
| quality rows 0.3, others 0.1 (**this notebook**) | **0.496** | **+0.016 to +0.040** | **1.475** |

The optimum is broad, which is reassuring for transfer: quality weight 0.3–0.5 and the rest 0.05–0.15 all land at
0.495–0.496. Dropping the low-quality rows entirely (weight 0) is worse (0.484), so they still help, just less.

**Tried and not better for this member:** larger pools (122k: 0.470, 120k: 0.461), per-row importance weights from a
host-vs-pool domain classifier (0.472), other C values at weight 1 (0.462–0.476), class balancing on weighted counts
(no change), refitting on pseudo-labelled test passages (worse in simulation).
